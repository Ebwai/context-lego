# Context Lego

DeepSeek Harness 的横向无限画布对话插件。支持点击节点展开问答卡片、沿祖先路径续聊，以及组合历史节点和提示词。

按 Harness 的 bundle 和 Host / Client 入口约定组织。包名沿用 `dsh-conversation-tree`，以承接已有插件配置和本机保存的树记录。

```text
context-lego/
├── package.json           包声明、bundle 和 client 元数据
├── cordis.patch.yml       将插件插入 Harness 的配置层
├── src/
│   ├── index.js           Host 插件入口
│   ├── history.js         原生历史读取、轮次校验和导入
│   └── client/
│       └── index.js       浏览器插件、画布和会话交互
├── scripts/
│   └── build.mjs          生成运行时入口
└── lib/                   构建产物，由 package exports 引用
    ├── index.js
    └── client.js
```

客户端源码采用 Harness 所需的 `window.__ModuleLoader__.load` 工厂格式，React 由宿主提供。Host 使用 Harness 的 Session 和消息构造函数。开发前运行 `npm install` 安装这些依赖。构建复制入口及历史组装模块。

在此目录运行 `npm run check` 检查语法，运行 `npm test` 验证原生消息及工具配对，运行 `npm run build` 更新 `lib/`，运行 `npm pack` 生成可安装插件包。修改 `src/` 后需要重新构建。修改 Host 入口或依赖后需要重新加载插件或重启 Harness。

在其他 Harness profile 安装时可执行 `dsh plugin --profile <名称> add F:/claude_project/context-lego`。当前本机 desktop profile 已通过本地目录链接加载此包。

树结构和卡片记录保存在桌面客户端的本地存储，Agent 执行记录由 Harness 的会话服务保存。

对话树支持新建、命名和切换多个画板。每个画板分别保存节点、系统提示词、工作区、模型和 Agent 预设，已有单画板数据保留在“画板 1”。草稿或目录选择尚未完成时不能切换画板；切换画板不会停止 Host 中的 Agent，返回后会恢复读取其执行结果。

画板、工作区、Agent 预设和模型收在单行紧凑工具栏中，长内容显示前缀及省略号，展开或悬停可查看完整信息。画板选择器旁的铅笔按钮进入重命名（保存确认，Escape 取消），加号新建画板；名称输入框只在编辑时出现。窄窗口中工具栏横向滚动，避免增加设置区的行数。

组合模式中可逐节点勾选，并选择是否将该节点到根节点的整条路径纳入（默认关闭）。按节点 ID 对共同祖先去重，再按层级、同层首次选中顺序组装；绿色节点表示实际已纳入的内容。新对话挂在已纳入的最长链路末端，其他选中来源用直线连接；后续从该对话继续分支时，保留其完整组合上下文。

普通节点（含系统根节点）悬停或键盘聚焦后显示加号，用于创建继承上下文的分支。顶部“新增积木节点”用于保存独立的提示词模板：积木不连接主树，使用方框节点标记，可在组合模式中勾选使用。

工作区使用 Harness 的 `workspaces` 官方服务与工作区列表；“选择文件夹”沿用 `dsh-client-ui-directory-picker-native` 的桌面 preload 桥接（普通 Web 使用 `uiWorkspace.pickDirectory()`），成功后通过官方 `workspaces.create({ path })` 注册并选择工作区。用户不需要手填路径。

除系统根节点外，每个节点均可点击“删除”，选择“只删除这个节点”或“删除此节点及以下全部节点”。仅删除当前节点时，直接子节点接到原父节点；删除整条分支时，旁支保留。正在执行的节点需先停止或完成后再删除。删除移除画板中的节点记录，保留 Harness 原始 Session，以免破坏仍在使用这些原生历史的其他节点。

节点卡片通过独立的 `SessionReference` 和原生 `SessionProvider` 绑定会话，使用 Harness 已安装的 `conversation.content` Component Factory（`variant: embedded`）。聊天、分析、工具动作、流式回复和输入框直接复用 `dsh-client-ui-conversation` 与 `dsh-client-ui-chat`，无需安装另一套聊天插件。卡片订阅原生事件登记新轮次，正常输入、停止、附件、审批和模型控件由原生会话处理。画板样式不覆盖原生内容区。

工具栏“资源”按钮位于“组合上下文”左侧，可随时调出可关闭、可拖动的资源卡片，拖动位置按画板保存。点击节点原生会话内的文件或网页时自动展开卡片，显示实际点击的资源；不同节点分别记住本次打开的资源，切换节点时跟随切换。文件内容、修改预览和网页使用 Harness 已安装的原生右侧栏组件，通过独立插槽适配嵌入，不需要另装预览插件。没有点击资源的节点显示原生引导页。

容量和历史组装属于插件内部命令，通过官方 `conversation.chat.commandview` 扩展点隐藏它们的展示；不覆盖普通命令、思考或工具动作。容量仍使用 Harness 的 token meter，其估算值在新节点输入区顶部标注为“约”。

在节点卡片中划选正文、分析或工具输出的文字，可使用选区菜单“解释”或“进一步询问”创建子分支。菜单中的“继承从根节点到当前节点的完整上下文”每次默认不勾选：不勾选只发送引用原文和本次问题，且不导入树根的自定义系统提示词；勾选则按根到当前节点的路径继承原生上下文。新节点保留引用原文和继承方式。点击菜单外、按 Escape、滚动或调整窗口大小会收起菜单，原生输入区内的选字不触发菜单。

默认分支在所需历史与已有前缀一致时，通过官方 `sessions.fork` 保留完整 Session 历史。手动选择节点时，Host 的 `/context-lego-history` 命令读取每个源会话在该轮结束时的有效消息，保留原生 system、user、assistant、developer、tool 消息，再由正常 Agent 循环发送新问题。工具请求与结果必须完整配对，独立会话发生工具标识冲突时会同步重命名配对标识。

新节点记录自己的轮次结束位置。旧节点从原 Harness 会话读取实际记录，并用卡片保存的原始提问替换旧版 JSON 引用包装。源会话丢失或轮次已被替换而无法单独恢复时，界面会报告错误。

缓存命中取决于提供商、模型、系统指令、工具定义和消息前缀是否匹配。保持原生消息结构有利于复用一致的前缀，跨分支重排后的命中仍由实际请求决定。
